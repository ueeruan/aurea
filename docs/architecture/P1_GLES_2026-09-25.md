# Android OpenGL ES fallback

Android now builds and ships both Vulkan and OpenGL ES. Startup prefers Vulkan;
if GPU/renderer initialization leaves no usable GPU, it shuts that engine down
and retries with ES. Failure of both paths returns the actual startup errors.
This is startup fallback, not automatic switching after a runtime driver crash.
The manifest no longer requires Vulkan and requires ES 3.1.

The ES backend implements the existing GPUBackend interface. It runs the same
composition, effects, animation, 3D, temporal sampling and export renderer as
Vulkan and Metal. No alternate project format or reduced effect catalog is used.
ES 3.1 and half-float color attachments are required; unavailable timestamp,
external-image and heap information is not fabricated. Video uses CPU planes.

Shaders are translated from the existing SPIR-V to ESSL 310 during the build,
using the same pinned SPIRV-Cross revision/license already used for Metal.
Android CMake builds the host translator separately, with a shared ABI build
lock; AUREA_GLES_COMPILER can supply a prebuilt tool. Shader binaries are cached
by driver, SPIR-V and generated ESSL, so translator changes invalidate binaries.

The backend handles context movement between initialization/render/export,
frame fences and deferred media release, uniform pages, byte-plane PBO readback,
compressed/mipmapped/cube textures and reversed-depth 3D. GL window presentation
flips vertically; offscreen upload, sampling and readback preserve the renderer's
coordinate convention. Transparent borders use the native extension when
available, otherwise exact single-level 2D bilinear/nearest coverage for effect
targets. Unsupported sampler combinations return errors.

## Real decoder transfer regression

Offscreen synthetic tests passed but actual MediaCodec video initially stalled
the emulator GL command transport. A standalone real-decoder regression
reproduced the stall immediately after uploading its mapped luma plane. Copying
the plane to owned CPU storage fixed it; retaining a nonzero GL row-length with
the copied data still passed, isolating the decoder-backed input pointer.
Uploads now pack into owned transfer memory and copy before returning. Scratch
retention is capped at 16 MiB; larger temporary storage is released after upload.
Scratch and CPU buffer mirrors are included in memory accounting.

## Executed validation

- ES GPU/export regression: 151 tests, 528,647 checks, zero failures after the
  shared 3D environment lifetime fix (commit 2f81f8e8).
- New native window test moves the context to another thread, compiles a pipeline
  inside a frame and presents to an ImageReader; captured red pixels are checked.
- New real MediaCodec test renders a decoded H.264 frame and checks visible output.
- Final combined run including both native regressions: 153 tests, 528,662
  checks, zero failures (gles-final-regression.log).
- Android x86_64 and arm64 debug builds and Kotlin tests passed.
- Actual app, API 35 host-GPU emulator: VFR + Timewarp RGB preview visible and
  correctly oriented, playback and background/resume exercised. The emulator
  hardware decoder failed during playback and the software fallback recovered.
- Actual app export: H.264 1280x720 at 30 fps, 90 frames, from a 21 fps composition
  with RGB offsets +3/0/-3. Independent FFmpeg comparison matched all 90 frames
  in every channel (zero presentation mismatches). The measured run took about
  4.5 seconds using the emulator's software encoder; this is not phone performance.
- Full shared-core host regression: 666 tests, zero failures, 201.18 seconds.
- iOS scope/resources/effect-contract static checks passed. Native Metal execution
  has not been performed on this Windows host.

Evidence: engine/build/android-p0/gles-app-fixed-preview.png,

Debug APKs accept `adb shell setprop debug.aurea.gpu gles` before process startup.
Use `adb shell setprop debug.aurea.gpu auto` to restore Vulkan preference, then
restart the app. Release builds ignore this override. The native test target is
enabled with AUREA_ANDROID_GLES_PROBE=ON; AUREA_GLES_MEDIA supplies an optional
device-local H.264 fixture. Use a bounded adb timeout for driver hang regressions.

Remaining validation: physical low-end Android devices and problematic Vulkan
drivers, iOS native build/execution, long real-media workloads, and measurements
of thermal behavior, memory and battery. This checkpoint does not complete P1–P10.
