# Texture memory accounting

`TextureDesc::estimated_bytes()` previously counted only mip level zero. That
underreported the transient pool, render graph and Metal resource bytes. Compressed
4x4 formats also undercounted small/non-aligned mip levels. The shared estimator
now sums every mip, rounds compressed blocks, accounts for faces/layers/volume
depth and samples, and saturates on overflow. Scene texture caching uses the same
calculation instead of an approximate 4/3 multiplier (wrong for thin textures).

Metal imported IOSurfaces were never added to owned texture bytes, but their
destruction subtracted from that counter. Releasing a video frame could therefore
erase the accounting for unrelated live textures. External texture release now
leaves owned bytes unchanged. The opt-in native iOS decoder regression includes
a Metal allocation/import/release check with a retained production decoder frame.

Validation: complete host suite passed (665 tests, zero failures, 185.43 seconds),
Android arm64 Debug assembly and Kotlin unit tests passed, and iOS symbol/scope/
project static checks passed. The native iOS regression has not been executed
on this Windows machine. This is a memory checkpoint, not completion of P1;
OpenGL ES fallback and transparent preview proxy generation remain outstanding.

## Decoder retirement off the render thread

`MediaManager::collect()` ran in `Engine::render_once()` and destroyed video
sources synchronously. Destroying a source joined its decoder/opening worker,
so a slow MediaCodec/AVFoundation operation stalled rendering despite running
decode itself on another thread. Layer deletion had the same join on the UI path.

Idle/deleted sources now enter one retirement worker. New decoder admission waits
for pending retirement so repeated replacement cannot grow an unbounded backlog
of platform sessions. Completion wakes rendering. Project/device teardown drains
the queue, including callbacks, before destroying their factory/context. Memory
trim reports queued closure accurately rather than claiming synchronous release.

Validation: a blocked-opening/blocked-decoding regression proves collect/delete
returns while the codec is blocked, new admission is held, shutdown waits, every
codec is destroyed, and the same layer can reopen. Full host suite: 666 tests,
zero failures, 194.40 seconds. Android x86_64 and arm64 builds and Kotlin tests
passed. On the API 35 emulator, playback/background/resume followed by temporal
RGB export produced 90 correct frames (independent three-channel comparison).
The goldfish hardware decoder failed after resume and recovered through the
existing platform software fallback. No ANR or crash was observed. Native iOS
execution remains pending; this lifecycle implementation is shared C++.
